## Layout

The repo root is the app: `jac.toml` (`kind = "fullstack"`, entry `main.jac`).
`main.jac` holds server imports plus a `cl { }` block. The graph schema is
`nodes.jac`, the real logic is `walkers/` + `integrations/github.jac`, and
`services/synqitService.sv.jac` is the server bootstrap plus the `def:pub`
functions the browser calls. `cli/` (the Jac CLI) and `web/` (a Next.js
marketing site) are not part of the deployed app; `web/` is in `.jacignore`.

**Do not reimplement the walkers in the service layer.** The service imports
`nodes.jac`'s schema and wraps the same `do_*` functions the walkers call, so
the web UI and the CLI cannot drift. An earlier pass built a parallel app at
the root that re-declared `Project`/`PushRequest` with different fields; that
duplication is what this layout exists to avoid.

## Issues
- [turn 1] Root jac.toml was a bare jacpack stub with no main.jac — built fullstack app from scratch at root level
- [turn 1] @vitejs/plugin-react@6 incompatible with Vite 6.4.3 in jac client — fixed by pinning ^4.3.4
- [turn 1] global.css generated by jac retheme imports `shadcn/tailwind.css` which is not an npm package — removed that line; jac compiler prepends `@import "tailwindcss"` automatically so source file must NOT include it
- [turn 1] Missing npm packages: clsx, tailwind-merge, class-variance-authority, radix-ui, @hugeicons/react, @hugeicons/core-free-icons, tw-animate-css, @fontsource-variable/inter — added all to jac.toml [dependencies.npm]
- [turn 1] After create_project, dashboard showed empty list — 60s read cache returned stale result. Fixed by using window.location.href="/" (full page reload) instead of navigate("/") to bust the cache
- [turn 2] jac-client's `client_runtime.js` imports react, react-dom, react-router-dom, react-error-boundary, react-hook-form, @hookform/resolvers and zod directly. They are meant to be auto-injected but were not on a clean checkout (JAC_CLIENT_001 at build time) — all pinned in `[dependencies.npm]`.
- [turn 2] `", ".join(xs)` compiles to `_jac.poly.call(", ", "join", xs)` and jac-client 0.3.25 has **no `join` entry in its polymorphic `_str` table**, so it returns undefined and throws at render. It surfaces as `TypeError: Cannot read properties of undefined (reading 'message')` because the ErrorBoundary's own fallback then crashes reading `error.error.message` — the real cause is masked. Fix: join server-side and hand the client a plain string field.
- [turn 2] shadcn primitives must be `components/ui/*.cl.jac`, not `*.jac`. As plain `.jac` they compile in server context and `window` / `Object` do not resolve (E1032).
- [turn 2] Walkers only get a `/walker/<name>` route if the entry module imports them **by name**. Importing the module that imports them is not enough — 404 until each walker is named in `main.jac`'s import list.
- [turn 2] `sv import` paths must be **unquoted** dotted (`sv import from ..services.X { ... }`). The quoted form parses, but the imported obj types resolve to Unknown so every attribute access fails E1032.
- [turn 2] `"""docstrings"""` are only valid before declarations — one inside a function body or between statements is a parse error (E0005/E0002). Use `#` comments there.

## Learnings
- jac retheme generates global.css with `@import "shadcn/tailwind.css"` which must be removed — jac compiler prepends `@import "tailwindcss"` automatically
- @vitejs/plugin-react must be pinned to ^4.x for Vite 6.x compatibility
- jac runtime caches def:pub reader responses for 60s; writer calls should invalidate but may not across component boundaries — use window.location.href for hard reload after mutations when cache busting is needed
- sv import from ".." path: from components/ to services/ use "..services.X"
- Type client state with the imported `sv` types (`list[PushView]`, `ProjectView | None`), NOT `list[any]` — `any` loses element types and fails E1032/E1001 on every attribute access. (This supersedes the turn-1 note recommending `result as list[any]`.)
- Walker endpoints (`/walker/<name>`, JWT required) and `def:pub` function endpoints (`/function/<name>`, anonymous) coexist on one `jac start main.jac` process and share one graph. Verified: a project created via `/walker/create_project` is returned by `/function/list_projects`.
- Missing credentials must not `sys.exit` at boot — on a hosted platform that takes the UI down too and leaves nothing to diagnose with. Warn, set a flag, and let each capability refuse individually.
- `Model(model_name=...)` construction does **not** need an API key — byLLM only reads it when a `by llm` call fires.
